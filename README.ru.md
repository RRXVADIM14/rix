# rix

Переносимый пакетный менеджер и сборщик пакетов из исходников в духе [pkgsrc](https://www.pkgsrc.org/), с USE-флагами как в Gentoo.

rix живёт в своём префиксе (по умолчанию `/opt/rix`) рядом с любой системой, которая у тебя уже стоит. Свои копии библиотек он собирает в этом префиксе, а от хоста берёт только libc и компилятор. Рецепт — несколько строк shell, обычно прямо из [книги BLFS](https://www.linuxfromscratch.org/blfs/).

С префиксом `/usr` rix становится системным пакетным менеджером для Linux From Scratch. Один инструмент на оба случая.

> **Статус:** ранняя, экспериментальная версия. Основа работает и проверена на тестовых рецептах, но настоящих рецептов пока два: `zlib` и `hello`.

## Возможности

- **Сборка из исходников:** скачивание, проверка sha256, кеш исходников, бинарные пакеты `.tar.xz`
- **Свой префикс:** в бинарники прописывается rpath, они работают без `LD_LIBRARY_PATH`
- **Зависимости:** для работы и только для сборки, правильный порядок, недостающие собираются и ставятся сами, циклы обнаруживаются
- **USE-флаги и настройки компиляции для отдельных пакетов**, как в Gentoo (`make.conf` + `package.use` + `package.env`)
- **Безопасная установка и удаление:** поиск конфликтов файлов, атомарная замена, отредактированные конфиги сохраняются (`.rixnew`), чужие папки не удаляются
- **Обновление, autoremove, поиск владельца файла, очистка кеша**
- **Только стандартная библиотека Python**, ничего доустанавливать не нужно

## Требования

- Linux
- Python 3.11+
- bash, компилятор C и то, что нужно рецептам (make, meson, cmake…)

## Быстрый старт

```sh
git clone https://github.com/RRXVADIM14/rix.git
cd rix

# Один раз: создать префикс и отдать его своему пользователю (единственный шаг с sudo)
sudo mkdir -p /opt/rix && sudo chown $USER: /opt/rix

./rix install hello            # собрать и поставить в /opt/rix
eval "$(./rix env)"            # подключить /opt/rix/bin и т.д. (добавь в ~/.bashrc)
hello
```

Скрипт `rix` можно положить в `PATH` ссылкой: `ln -s "$PWD/rix" ~/.local/bin/rix`.

## Команды

| Команда | Что делает |
|---|---|
| `rix search <текст>` | Поиск рецептов по имени и описанию |
| `rix build <пкг>…` | Собрать пакеты (недостающие зависимости сначала ставятся в префикс) |
| `rix install <пкг\|файл.tar.xz>…` | Поставить по имени (с автоматической сборкой) или из файла пакета |
| `rix remove <пкг>…` | Удалить пакеты (откажется, если от них кто-то зависит) |
| `rix upgrade` | Пересобрать пакеты, у которых сменилась версия рецепта или USE-флаги |
| `rix autoremove` | Удалить зависимости, которые больше никому не нужны |
| `rix list` | Установленные пакеты |
| `rix info <пкг> [--files]` | Подробности о пакете, по желанию со списком файлов |
| `rix owns <путь>` | Какому пакету принадлежит файл |
| `rix deps <пкг>…` | Зависимости в порядке сборки, со статусом |
| `rix use <пкг>…` | USE-флаги и откуда взялись их значения |
| `rix clean` | Удалить папки сборки и файлы, которые не нужны текущим рецептам |
| `rix env` | Команды для подключения префикса в шелле |

Глобальные опции пишутся перед командой: `--prefix DIR` (или `$RIX_PREFIX`) и `--root DIR` (или `$RIX_ROOT`, для подготовки другой системы, например образа).

## Как написать рецепт

Рецепт — папка `recipes/<имя>/` с двумя файлами.

`package.toml`:

```toml
name = "zlib"
version = "1.3.1"
description = "Compression library implementing the deflate method"
source = ["https://zlib.net/fossils/zlib-1.3.1.tar.gz"]
sha256 = ["9a93b2b7dfdac77ceba5a558a580e74667dd6fede4585b91eefb60f03b72df23"]
depends = []          # нужен для работы (и для сборки)
makedepends = []      # нужен только для сборки

[use]
static = { default = false, description = "Also install the static library libz.a" }

[use_depends]         # дополнительные зависимости, если флаг включён
# ssl = ["openssl"]
```

`build` — bash-скрипт, он запускается в распакованных исходниках:

```sh
./configure --prefix="$PREFIX"
make
make DESTDIR="$PKG" install

if ! use static; then
    rm -f "$PKG$PREFIX/lib/libz.a"
fi
```

Правила:
- `--prefix="$PREFIX"`, желательно ещё `--sysconfdir="$SYSCONFDIR"`;
- установка через `DESTDIR="$PKG"`.

Система сборки rix не важна: autotools, meson и cmake работают одинаково. Скрипт получает переменные `PKG`, `SRC`, `NAME`, `VERSION`, `PREFIX`, `SYSCONFDIR`, `LOCALSTATEDIR`, `USE`, `CFLAGS`, `CXXFLAGS`, `LDFLAGS`, `MAKEFLAGS` и хелперы `use`, `use_enable`, `use_with`, `meson_use`, `meson_feature`, `cmake_use`.

Если в источнике нет `://`, это файл рядом с рецептом, например патч: `patch -Np1 -i "$SRC/fix.patch"`.

## Настройка

`~/.config/rix/config.toml` необязателен. Пример — в [`config.example.toml`](config.example.toml).

```toml
prefix = "/opt/rix"
cflags = "-O2 -pipe -march=x86-64-v2"
jobs = 8
use = ["-doc"]                 # глобальные USE-флаги; "-flag" выключает

[package.zlib]                 # настройки для конкретного пакета
use = ["static"]
cflags = "-O3 -pipe -march=x86-64-v2"
```

Приоритет для USE-флагов: значение из рецепта < глобальные `use` < `[package.<имя>]`.
Приоритет для флагов компиляции: окружение (`CFLAGS=-O0 rix build x`) > `[package.<имя>]` > глобальные > по умолчанию.

Если сменить USE-флаги пакета, rix пересоберёт его при следующем `install` или `upgrade`.

## Системный режим (LFS)

```sh
rix --prefix /usr install zlib
```

С префиксом `/usr` конфиги идут в `/etc`, база — в `/var/db/rix`, а после изменения библиотек запускается `ldconfig`. Так rix управляет системой Linux From Scratch.

## Ограничения

- Зависимости указываются только по имени, без условий на версию
- Во время сборки видны библиотеки хоста. Если зависимость не указана в рецепте, она молча возьмётся с хоста (pkgsrc прячет такие библиотеки через buildlink, rix пока нет).
- Пакет работает только в том префиксе, для которого собран
- Нет подписей пакетов и удалённого репозитория бинарников
